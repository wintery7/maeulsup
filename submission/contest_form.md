## 21. 제안 내용 (네이버 폼 2,000자 제한)

```
전통마을숲 데이터로 아이에게 들려주는 '1분 숲 이야기' 서비스를 만들며 실제로 막혔던 점을 중요한 순서로 정리했습니다. 수치는 전체 1,106건을 직접 받아 프로그램으로 센 결과입니다.

1. 역사·문화 조사 글이 255바이트에서 잘립니다 (데이터 품질)
- 불편: 역사조사내용 118건, 문화조사내용 24건이 EUC-KR 기준 253~254바이트(약 150자)에서 끝납니다. 이 142개 중 마침표로 끝나는 것은 4개뿐이고 나머지는 "500여본 식"처럼 문장 중간에서 끊깁니다. '숲에 사는 식물 정보'의 식물이야기설명도 179건 전부 49~50바이트에서 잘려 있습니다.
- 제안: 원본 DB 칸 크기(255바이트, 50바이트)를 늘려 전문을 제공해 주세요. 어렵다면 명세에 길이 제한만이라도 표시해 주세요.
- 기대 효과: 이 데이터의 가장 큰 가치는 마을숲에 얽힌 이야기입니다. 전문이 있으면 지역 관광, 초등 '우리 고장' 교육, 마을 안내판으로 쓰임이 넓어집니다.

2. '위치도'인데 좌표가 없고 주소 형식이 제각각입니다 (API 사용성)
- 불편: 위치 정보는 소재지 주소 텍스트뿐이고, 시도 약칭 80건, 시·군 누락 48건, 시도 누락 10건이라 좌표 변환이 한 번에 되지 않았습니다.
- 제안: 대표 지점 좌표(WGS84) 필드 추가, 표준 행정구역 명칭 통일.
- 기대 효과: 지도 서비스에 바로 연결할 수 있습니다.

3. 빈 값, 중복, 깨진 값이 정리되어 있지 않습니다 (데이터 품질)
- 불편: 역사조사내용 63.2%, 문화조사내용 73.1%가 비어 있는데 빈 값이 공백 한 칸으로 와서 그냥 세면 0%로 나옵니다. 다른 숲인데 설명이 똑같은 기록 18묶음 72건, 이름이 "195 동일"인 기록, '?'로 깨진 글자가 섞인 기록 6건이 있습니다.
- 제안: 빈 값 표기 통일, 중복·이상값·인코딩 정기 점검.

4. 명세와 실제 값이 다르고 필드 뜻을 알기 어렵습니다 (API 사용성)
- 불편: 구역면적이 중앙값 0.24, 최대 157.96으로 명세 단위와 맞지 않아 보입니다. 필드명이 histrexmnncont 같은 약어이고, 수종 표기가 식물 정보와 달라('해송'과 '곰솔') 두 데이터를 잇기 어렵습니다.
- 제안: 단위 정정, 필드별 한글 설명과 예시 값, 산림청 데이터 간 수종명 통일.

5. 제공 형식이 제한적입니다 (제공 형식)
- 불편: API는 XML만, 식물 정보 CSV는 CP949라 Mac 엑셀과 구글 시트에서 한글이 깨집니다.
- 제안: JSON 응답과 UTF-8 파일 제공.

6. 사진이 없고 다른 기관 데이터와 잇기 어렵습니다 (서비스 연계)
- 불편: 사진 필드가 없어 관광공사·국가유산청 자료에서 이름과 좌표로 찾았지만, 숲이 아닌 근처 명소 사진이 많았고 천연기념물 숲도 지정번호가 없어 직접 짝을 맞췄습니다. 이야기를 만든 104곳 중 숲 사진을 찾은 곳은 12곳뿐입니다.
- 제안: 대표 사진 필드(공공누리 유형 포함)와 국가유산 지정번호 같은 연결 식별자 추가.
- 기대 효과: 관광·문화유산 데이터와 바로 이어 쓸 수 있습니다.

같은 문제를 겪지 않도록 정리한 데이터(CSV·JSON·GeoJSON)와 API 호출 예제를 https://maeulsup.vercel.app/#kit 에 공개했습니다.
```
